1. Introduction & Project Overview

CitiSolve is a civic complaint management system designed to allow citizens to submit, track, and manage complaints related to public services. The application provides a user-friendly interface where citizens can register, log in, submit new complaints, and view the status of their previously submitted complaints.

The project is built as a Single Page Application (SPA) using React.js, which enables seamless navigation between different views without full-page reloads. The frontend communicates with a backend REST API server running on localhost:5000 for data persistence and authentication.

Key Features

  • User Registration and Login with token-based authentication
  • Submit new civic complaints
  • View and track personal complaint history
  • Responsive navigation bar with dynamic content based on login state
  • Client-side routing for a smooth single-page experience

4. Application Architecture & Data Flow

The CitiSolve application follows a standard React SPA architecture with unidirectional data flow. Below is a high-level diagram showing how the different layers of the application interact.

┌─────────────────────────────────────────────────────────────┐ │ BROWSER │ │ │ │ index.html │ │ └── <div id="root"> │ │ └── main.jsx │ │ └── <BrowserRouter> │ │ └── <App /> │ │ │ │ │ ┌───────────┴───────────┐ │ │ │ │ │ │ <NavBar /> <Routes> │ │ (always visible) (page swap) │ │ │ │ │ ┌────┬────┬──────┴─────┐ │ │ │ │ │ │ │ │ │ Home Login Register My Submit │ │ Comp Comp │ │ │ │ ┌──────────────┐ ┌─────────────────┐ │ │ │ UserContext │ │ services/api │ │ │ │ (auth state) │ │ (Axios → API) │ │ │ └──────────────┘ └────────┬────────┘ │ │ │ │ │ ┌──────────▼──────────┐ │ │ │ Backend REST API │ │ │ │ localhost:5000/api │ │ │ └────────────────────┘ │ └─────────────────────────────────────────────────────────────┘

Figure 2: Application architecture diagram

Data Flow Explanation

  1. The browser loads index.html, which includes main.jsx as a module script.
  2. main.jsx wraps the entire application in <BrowserRouter> for client-side routing.
  3. The App component renders the NavBar (persistent) and a <Routes> block (swaps page content based on URL).
  4. Page components use React hooks (useState, useNavigate) to manage local state and navigation.
  5. Authentication tokens are stored in localStorage and read by the NavBar to toggle login/logout UI.
  6. The api.js service creates an Axios instance pointed at the backend for HTTP requests.

6. Root Component – App.jsx

File: /src/App.jsx

Type: Functional Component

Props: None (root component)

The App component is the root of the application's component tree. It is responsible for two primary tasks: rendering the persistent NavBar component and defining the route configuration using React Router's <Routes> and <Route> components. 

import { Routes, Route } from "react-router-dom";
import Home from './pages/Home';
import Login from './pages/Login';
import Register from './pages/Register';
import MyComplaints from './pages/MyComplaints';
import SubmitComplaints from './pages/SubmitComplaints';
import NavBar from "./comonents/Navbar";

function App() {
    return (
        <div>
            <NavBar />

            <Routes>
                <Route path="/" element={<Home />} />
                <Route path='/login' element={<Login />} />
                <Route path="/register" element={<Register />} />
                <Route path="/myComplaints" element={<MyComplaints />} />
                <Route path="/submitComplaints" element={<SubmitComplaints />} />
            </Routes>
        </div>
    )
}

export default App;

Components Used Inside App

ComponentRoleRendered By
<NavBar />Persistent navigation headerAlways rendered above routes
<Routes>Route container from React RouterWraps all route definitions
<Route>Individual route definitionMaps URL path to page component

React Router Concepts

ConceptExplanation
<Routes> A container that renders the first <Route> that matches the current URL
<Route path="..." element={...}> Defines a mapping between a URL path and a React component to render
path="/" Matches the root/home URL of the application
element={<Component />} The React element (JSX) to render when the path matches

    return (
        <nav>
            <div>
                <Link to="/">
                    <h1>🏛️ CitiSolve</h1>
                </Link>
            </div>

8.2 Login Page

File: /src/pages/Login.jsx

Route: /login

Props: None

Hooks Used: useState, useNavigate

The Login page is the most feature-rich page component in the current project. It implements a complete login form with controlled inputs, form submission handling, localStorage-based authentication, and programmatic navigation. 

import { React, useState } from "react";
import { useNavigate } from "react-router-dom";

function Login() {
    const navigate = useNavigate();
    const [email, setEmail] = useState("");
    const [password, setPassword] = useState("");

    const handleLogin = (e) => {
        e.preventDefault();
        localStorage.setItem("token", "dummy-jwt-token");
        localStorage.setItem("username", email);
        navigate("/");
    };

    return (
        <>
            <form onSubmit={handleLogin}>
                <input
                    type="email"
                    placeholder="Email"
                    value={email}
                    onChange={(e) => setEmail(e.target.value)}
                />
                <input
                    type="password"
                    placeholder="Password"
                    value={password}
                    onChange={(e) => setPassword(e.target.value)}
                />
                <button type="submit">Login</button>
            </form>
        </>
    );
}

export default Login;

Detailed Breakdown of Login Component

Hooks Used

HookImportPurpose
useState from "react" Creates reactive state variables for email and password form fields
useNavigate from "react-router-dom" Returns a navigate function for programmatic route changes

State Variables

StateInitial ValueSetterPurpose
email "" (empty string) setEmail Stores the user's email input value
password "" (empty string) setPassword Stores the user's password input value

Event Handlers

HandlerTriggerActions Performed
handleLogin(e) onSubmit (form submission) 1. Calls e.preventDefault() to prevent page reload
2. Stores a dummy JWT token in localStorage
3. Stores the email as username in localStorage
4. Navigates to the home page (/) using navigate("/")
onChange (email) User types in email field Calls setEmail(e.target.value) to update state
onChange (password) User types in password field Calls setPassword(e.target.value) to update state

Controlled Components Pattern

The Login form uses the Controlled Components pattern, which is a core React concept. In this pattern, the form input values are controlled by React state rather than by the DOM:

  • The value prop of each <input> is bound to a state variable (email, password)
  • The onChange event handler updates the state when the user types
  • React re-renders the component with the new state, keeping the input in sync

9. Context – UserContext

File: /src/context/UserContext.jsx

Status: Empty (placeholder for future implementation)

The UserContext.jsx file is reserved for implementing React's Context API for global user state management. When implemented, it will provide authentication state (user data, token) to all components without prop drilling.

What is React Context?

React Context is a mechanism for passing data through the component tree without having to pass props manually at every level. It consists of three parts:

PartAPIPurpose
Context Object React.createContext() Creates a context with a default value
Provider <Context.Provider value={...}> Wraps components that need access to the context value
Consumer useContext(Context) Hook that reads the current context value in any child component

Planned Usage

Once implemented, the UserContext would typically store authentication state (token, username, login/logout functions) and wrap the <App /> component in main.jsx, making auth data available throughout the app.

10. Services – API Configuration

File: /src/services/api.js

The API service file creates and exports a pre-configured Axios instance for making HTTP requests to the backend server. 

import axios from "axios";

const API = axios.create({
    baseURL: "http://localhost:5000/api",
});

export default API;

Key Concepts

ConceptExplanation
axios.create() Creates a new Axios instance with custom configuration. All requests made through this instance will use the specified baseURL as a prefix.
baseURL The base URL prepended to all relative request paths. For example, API.get("/users") would request http://localhost:5000/api/users.
Default Export The configured Axios instance is exported as the default export, allowing other files to import it as import API from './services/api'.

Typical Usage in Components

import API from '../services/api';

// GET request
const response = await API.get("/complaints");

// POST request
await API.post("/complaints", { title: "...", description: "..." });

// With authentication header
API.defaults.headers.common['Authorization'] = `Bearer ${token}`;

12. React Hooks Used in the Project

React Hooks are functions that allow functional components to use state and other React features. Below is a comprehensive reference of all hooks used in the CitiSolve project.

HookSourceUsed InPurpose
useState react Login.jsx Creates reactive state variables that trigger re-renders when updated
useNavigate react-router-dom Login.jsx Returns a function to programmatically change the URL/route

useState – In Detail

Syntax: const [stateVar, setStateVar] = useState(initialValue);

  • Returns an array with two elements: the current state value and a setter function
  • Calling the setter function triggers a component re-render with the new value
  • The initial value is only used during the first render

Example from Login.jsx:

const [email, setEmail] = useState("");     // email = "", setEmail updates it
const [password, setPassword] = useState(""); // password = "", setPassword updates it

useNavigate – In Detail

Syntax: const navigate = useNavigate();

  • Returns a navigate function that changes the current URL without a full page reload
  • navigate("/") navigates to the home route
  • navigate(-1) goes back one step in browser history
  • Must be called inside a component wrapped by <BrowserRouter>
